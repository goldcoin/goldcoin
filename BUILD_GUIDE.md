# Gold Coin Enterprise Build System Guide

## Overview

This document provides a comprehensive guide to the Gold Coin enterprise build system, covering Linux binaries, Windows binaries (CLI-only and GUI), and the Windows installer. All commands below are run from the **repository root** and are the exact, tested sequence for a full rebuild of every binary.

## Quick Reference: Full Build Sequence

```bash
# One-time: build dependencies (skip if depends/ already built — check with `make status`)
make deps-linux                 # Linux deps → depends/x86_64-pc-linux-gnu/
make deps-windows                # Windows deps incl. Qt6 → depends/x86_64-w64-mingw32/
                                  # (use deps-windows-no-qt instead if you don't need the GUI)

# Every rebuild:
make linux JOBS=8                # → build/linux/bin/{goldcoind,goldcoin-cli,goldcoin-tx}
make windows JOBS=8              # → build/windows/bin/{goldcoind.exe,goldcoin-cli.exe,goldcoin-tx.exe}
make windows-qt JOBS=8           # → build/windows-qt/bin/{goldcoin-qt.exe,goldcoind.exe,goldcoin-cli.exe,goldcoin-tx.exe}
make windows-installer           # → goldcoin-<version>-win64-setup.exe (repo root)
```

`JOBS` defaults to `nproc` if omitted. `linux`, `windows`, and `windows-qt` each do a **full clean rebuild** (they `rm -rf` their build directory first), so re-running any of them after a source change is safe and always picks up your latest edits.

## First Time Setup

### Step 1: Build Dependencies (Required, once)

```bash
make deps-linux              # For Linux builds
make deps-windows            # For Windows builds WITH Qt GUI (builds Qt6, slow — ~hours)
make deps-windows-no-qt      # For Windows builds WITHOUT Qt GUI (much faster)
```

Dependencies are cached under `depends/` and persist between builds — you only need to run these once (or after a `depends/packages/*` change).

### Step 2: Build Binaries

```bash
make linux JOBS=8            # Linux binaries → build/linux/bin/
make windows JOBS=8          # Windows CLI binaries → build/windows/bin/
make windows-qt JOBS=8       # Windows GUI + CLI → build/windows-qt/bin/
```

### Step 3: Package the Windows Installer (optional, requires windows-qt build)

```bash
make windows-installer
```

Produces `goldcoin-<version>-win64-setup.exe` in the repo root — an NSIS installer bundling `goldcoin-qt.exe`, `goldcoind.exe`, `goldcoin-cli.exe`, `COPYING`, `README.md`, and `doc/`. Requires `makensis` (`sudo apt install nsis` if missing).

### Build Flow Logic: Separation of Concerns

The build system implements a clean **two-phase approach** to prevent cross-contamination:

#### Phase 1: Dependency Building
1. **User Command**: `make deps-windows` or `make deps-windows-no-qt` (from repository root)
2. **GNUmakefile**: Calls `make -C depends HOST=x86_64-w64-mingw32 [NO_QT=1] -j8`
3. **Depends Makefile**:
   - Target: `all` → `install` → `$(host_prefix)/share/config.site`
   - Dependency: `$(host_prefix)/.stamp_$(final_build_id)`
   - Requires: All `$(native_packages)` + `$(packages)` built and cached
4. **Final Output**: `depends/x86_64-w64-mingw32/` with complete toolchain (OpenSSL, libevent, ZeroMQ, BDB, miniupnpc, and — for the GUI — Qt6)

#### Phase 2: Binary Compilation
1. **User Command**: `make windows`, `make windows-qt`, or `make linux` (from repository root)
2. **Dependency Verification**: Checks for required libraries, fails fast with a clear message if missing
3. **Clean Rebuild**: Wipes and recreates `build/<target>/` (via a fresh `cmake` configure), then builds with the generated toolchain file
4. **Read-Only Access to depends/**: Binary compilation never modifies `depends/`
5. **Final Output**: Binaries in `build/<target>/bin/`

#### Phase 3: Installer Packaging (Windows GUI only)
1. **User Command**: `make windows-installer`
2. Regenerates `share/setup.nsi` from `share/setup.nsi.in`, substituting package name/version (pulled live from `src/version_info.h` and `CMakeLists.txt`) and pointing file references at `build/windows-qt/bin/`
3. Runs `makensis share/setup.nsi` to produce the installer in the repo root

#### Critical Engineering Principle
**Binary compilation commands cannot modify the depends system.** This prevents:
- Cache invalidation from build system changes
- Accidental dependency rebuilds during binary compilation
- Cross-contamination between dependency building and binary compilation phases
- Multi-hour OpenSSL/Qt6 rebuilds when only compiling binaries

### 📋 System Requirements

**Toolchain (Windows cross-compilation):**
- The mingw cross-compiler **must be the `-win32` thread-model variant**, not `-posix`: `x86_64-w64-mingw32-gcc-win32` / `x86_64-w64-mingw32-g++-win32`. This is because the depends-built Qt6 static libraries were compiled with the win32 thread model; linking against the posix-variant `libgcc.a` produces `undefined reference to __gthr_win32_*` errors at final link. `depends/x86_64-w64-mingw32/share/toolchain.cmake` (and the block in `GNUmakefile` that generates it) are already set to `-win32` — don't change this back to `-posix`.
- `makensis` (NSIS) is required for `make windows-installer`: `sudo apt install nsis`.

**For C++23 Support:**
- MinGW GCC 13 (either thread-model variant supports C++23; just make sure it's the `-win32` one per above)
- System GCC 13 for Linux builds

## Troubleshooting Guide

### Common Issues

1. **`undefined reference to __gthr_win32_*` at final link (goldcoin-qt.exe / goldcoind.exe)**
   - Cause: `toolchain.cmake` is pointing at the `-posix` mingw compiler instead of `-win32`
   - Solution: Check `depends/x86_64-w64-mingw32/share/toolchain.cmake` — `CMAKE_C_COMPILER`/`CMAKE_CXX_COMPILER`/`CMAKE_AR`/`CMAKE_RANLIB` should all reference the `-win32` suffixed binaries
   - Verify: `x86_64-w64-mingw32-g++-win32 -v` should print `Thread model: win32`

2. **`expected unqualified-id before string constant` on `PACKAGE_NAME` (goldcoingui.cpp / splashscreen.cpp / utilitydialog.cpp)**
   - Cause: `bitcoin-config.h`'s `#define PACKAGE_NAME` macro collides with the `inline constexpr auto PACKAGE_NAME` in `src/qt/goldcoin_constants.h`
   - Solution: Already fixed — `goldcoin_constants.h` `#undef`s the macro before declaring the constant. If this regresses, check that undef is still present.

3. **`undefined reference to qInitResources_bitcoin()`**
   - Cause: `Q_INIT_RESOURCE(bitcoin)` in `src/qt/goldcoin.cpp` referencing the old pre-rename resource name; the actual file is `src/qt/goldcoin.qrc`
   - Solution: Already fixed to `Q_INIT_RESOURCE(goldcoin)`.

4. **`multiple definition of q_ssl_sess_set_new_cb`**
   - Cause: A manual stub in `CMakeLists.txt` conflicting with the real symbol from the statically-linked OpenSSL TLS backend plugin
   - Solution: Already fixed — the stub was removed from `CMakeLists.txt`.

5. **`No rule to make target '.../lib/libQt6BundledZLIB.a'`**
   - Cause: Qt's cross-build for the mingw target only produced this bundled-zlib archive for the **native** host-tools build, not the target; Qt's exported CMake config still references it for the target too
   - Workaround: Copy the real (target-arch) zlib archive to the expected filename:
     ```bash
     cp depends/x86_64-w64-mingw32/lib/libz.a depends/x86_64-w64-mingw32/lib/libQt6BundledZLIB.a
     ```
   - Note: This lives under `depends/`, which is not tracked by git, so this workaround must be reapplied if `depends/x86_64-w64-mingw32` is ever rebuilt from scratch.

6. **`share/setup.nsi` has hardcoded paths from another machine / missing `.exe` extensions**
   - Cause: `share/setup.nsi` is a *generated* file (from `share/setup.nsi.in`); a stale copy may have been committed from a different environment
   - Solution: Just run `make windows-installer` — it regenerates `share/setup.nsi` fresh every time using values pulled from `src/version_info.h` and `CMakeLists.txt`.

7. **Windows Dependencies Missing**
   - Check: `make status`
   - Solution: Run `make deps-windows` (with Qt) or `make deps-windows-no-qt` (without) first
   - Verify: `ls depends/x86_64-w64-mingw32/lib/libcrypto.a` should exist

## Emergency Recovery

If builds become corrupted:
1. Check git status for modifications
2. Consider reverting to last known working state
3. Clean build directories: `rm -rf build/linux build/windows build/windows-qt` (safe — these are regenerated fresh on every `make linux`/`windows`/`windows-qt` run anyway)
4. Preserve cached packages: `depends/built/` if valid
5. Restart from clean state
